# План задач PersonalAssistant

## Как устроен список

- Бизнесовые задачи имеют числовые ID: `010`, `011` и далее.
- Технический долг и найденные проблемы имеют ID `TD-001`, `TD-002` и далее.
- После выполнения задача исчезает из этого файла, но навсегда остается в `docs/tasks/`.
- ID не переиспользуются и не меняются, поэтому по нему можно найти ветку, коммит и архив.

## Бизнесовые задачи

### MVP 1

Цель MVP 1 — дать пользователю законченный цикл учета обязательных платежей: создать платеж, увидеть его, отметить оплату, посмотреть историю, получить статистику и напоминание.

### Задача 015. Переименование предметной области

- заменить пользовательские формулировки «платеж» на «регулярный расход» там, где это улучшает смысл;
- исключить ежедневную периодичность из поддерживаемых вариантов;
- сохранить совместимость с уже созданными еженедельными, ежемесячными, ежегодными и однократными записями.

### Задача 020. Snooze напоминаний

- кнопка «Напомнить позже»;
- варианты через час, сегодня вечером и завтра;
- хранить snooze отдельно от `DueDate`;
- учитывать часовой пояс пользователя.

## Технический долг и качество

### TD-001. Интеграционные проверки и эксплуатация

- integration tests с PostgreSQL;
- проверка изоляции пользователей;
- проверка восстановления диалога после перезапуска;
- health endpoint;
- структурированные логи;
- безопасное применение миграций.

### TD-002. Идемпотентность Telegram Update

- постоянный журнал обработанных Telegram Update для полной идемпотентности;

### TD-003. Декомпозиция Telegram-слоя

- декомпозиция `TelegramPollingService` на маршрутизацию, форматирование и обработчики команд;
- разбиение длинных сообщений истории и статистики;

### TD-004. Единый контракт Telegram UI

- вынести оставшиеся пользовательские тексты и callback-сценарии из polling-класса;
- перейти с анализа текста ответа для выбора клавиатуры на явные результаты application-сценариев;
- разделить обработчики команд и callback-обработчики на небольшие классы.
