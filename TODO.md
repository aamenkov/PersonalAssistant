# План задач PersonalAssistant

## Как устроен список

- Бизнесовые задачи имеют числовые ID: `010`, `011` и далее.
- Технический долг и найденные проблемы имеют ID `TD-001`, `TD-002` и далее.
- После выполнения задача исчезает из этого файла, но навсегда остается в `docs/tasks/`.
- ID не переиспользуются и не меняются, поэтому по нему можно найти ветку, коммит и архив.

## Бизнесовые задачи

### MVP 1

Цель MVP 1 — дать пользователю законченный цикл учета обязательных платежей: создать платеж, увидеть его, отметить оплату, посмотреть историю, получить статистику и напоминание.

### Задача 010. Напоминания

- `BackgroundService`;
- напоминания до даты, в день платежа и после просрочки;
- учет часового пояса;
- защита от повторной отправки за один день;
- разные сообщения для обычных и автоматических платежей.

### Задача 011. Настройки пользователя

- время отправки напоминаний;
- валюта по умолчанию;
- повторное изменение часового пояса;
- единое меню `/settings`.

### Задача 012. Пользовательский интерфейс сценариев

- заменить текстовые варианты выбора периодичности и подтверждения на русские кнопки;
- показывать основное меню кнопок после `/start` и после выбора часового пояса;
- сделать выбор часового пояса понятнее: показывать UTC-смещение и пояснять, что его можно изменить в `/settings`;
- при выборе даты предлагать сегодняшнюю дату кнопкой и запрашивать дату только после отказа.

### Задача 013. Настройки валюты и уведомлений

- считать валюту по умолчанию пользовательской настройкой и не спрашивать её при каждом добавлении платежа;
- оставить возможность изменить валюту в `/settings`;
- добавить индивидуальные настройки уведомлений: время отправки и количество дней до напоминания.

### Задача 014. Список разрешённых пользователей

- заменить одиночный `TELEGRAM_ALLOWED_USER_ID` на список Telegram User ID;
- сохранить безопасное поведение: при пустом списке ограничение отключено, при заполненном доступны только перечисленные пользователи.

### Задача 015. Переименование предметной области

- заменить пользовательские формулировки «платеж» на «регулярный расход» там, где это улучшает смысл;
- исключить ежедневную периодичность из поддерживаемых вариантов;
- сохранить совместимость с уже созданными еженедельными, ежемесячными, ежегодными и однократными записями.

## Технический долг и качество

### TD-001. Интеграционные проверки и эксплуатация

- integration tests с PostgreSQL;
- проверка изоляции пользователей;
- проверка восстановления диалога после перезапуска;
- health endpoint;
- структурированные логи;
- безопасное применение миграций.

### TD-002. Идемпотентность Telegram Update

- постоянный журнал обработанных Telegram Update для полной идемпотентности;

### TD-003. Декомпозиция Telegram-слоя

- декомпозиция `TelegramPollingService` на маршрутизацию, форматирование и обработчики команд;
- разбиение длинных сообщений истории и статистики;

### TD-006. Устойчивость к сетевым ошибкам Telegram API

- не завершать пользовательский сценарий необработанным исключением при временной недоступности `api.telegram.org`;
- добавить повторные попытки с ограниченной задержкой и понятное логирование;
- не допускать бесконечного спама одинаковыми ошибками в логах.

### TD-007. Активное основное меню

- вынести reply-клавиатуру главного меню в отдельный компонент/строитель;
- обеспечить единый доступ к основным сценариям через кнопки, сохранив команды;
- проверить поведение меню после `/start` и после восстановления состояния.

## Когда можно запускать

### Технический запуск

Уже возможен после настройки `TELEGRAM_BOT_TOKEN`, PostgreSQL и применения миграций. Текущие команды: `/start`, `/settings`, `/add`, `/payments`, `/upcoming`, `/edit`, `/disable`, `/pay`, `/history`, `/stats`, `/help`.

### Ограниченный запуск для одного пользователя

Возможен после задачи 009. Доступны редактирование, отключение, отметка оплаты, история и статистика; запуск можно ограничить одним Telegram User ID.

### MVP 1 для регулярного использования

Рекомендуется после бизнесовых задач 010–011 и технического долга TD-001. Тогда появятся напоминания, пользовательские настройки, интеграционные проверки и эксплуатационные проверки.
