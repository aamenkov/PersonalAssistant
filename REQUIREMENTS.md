# Требования

## Назначение

PersonalAssistant должен помогать одному пользователю учитывать обязательные и регулярные расходы.

## Функциональные требования

- **FR-001**: `/start` регистрирует или обновляет Telegram-пользователя.
- **FR-009**: при первом `/start` пользователь выбирает часовой пояс, который используется для локального времени напоминаний.
- **FR-010**: пользователь может изменить часовой пояс через `/settings`.
- **FR-002**: пользователь может создавать платеж через последовательный сценарий `/add`.
- **FR-003**: пользователь видит все активные платежи через `/payments` и ближайшие 7 дней через `/upcoming`.
- **FR-004**: оплата создает неизменяемую историческую транзакцию и рассчитывает следующий срок.
- **FR-005**: бот показывает статистику отдельно по валютам.
- **FR-006**: бот хранит и показывает историю оплат.
- **FR-007**: бот отправляет настраиваемые напоминания.
- **FR-008**: многошаговые диалоги восстанавливаются после перезапуска.

## Бизнес-правила

- **BR-001**: сумма больше нуля, название обязательно.
- **BR-002**: активный платеж имеет дату следующего платежа.
- **BR-003**: история хранит фактически оплаченную сумму и не меняется при редактировании платежа.
- **BR-004**: однократный платеж деактивируется после оплаты.
- **BR-005**: неактивные платежи не входят в напоминания и плановую статистику.
- **BR-006**: месячные/годовые даты ограничиваются последним днем целевого месяца.
- **BR-007**: доступ к данным проверяется по владельцу.
- **BR-008**: часовой пояс принимается только после проверки через `TimeZoneInfo`.
- **BR-009**: транзакция хранит ожидаемую сумму и валюту на момент оплаты, чтобы последующее редактирование платежа не меняло прошлую статистику.

## Нефункциональные требования

- **NFR-001**: .NET 8, ASP.NET Core, EF Core, PostgreSQL и Docker Compose.
- **NFR-002**: секреты только в окружении/User Secrets.
- **NFR-003**: технические даты UTC, отображение по часовому поясу пользователя.
- **NFR-004**: повторная обработка Telegram Update и напоминаний идемпотентна.
- **NFR-005**: ошибки логируются без секретов.
- **NFR-006**: перед запуском polling приложение проверяет обязательную конфигурацию и применяет EF Core миграции.
- **NFR-007**: для ограниченного запуска можно разрешить доступ только одному Telegram User ID.

## Ограничения MVP

Нет банковских интеграций, конвертации валют, распознавания чеков, голосового управления, веб-интерфейса, совместных аккаунтов и AI-исполнения произвольных поручений.
