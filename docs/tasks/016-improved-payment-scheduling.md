# Задача 016. Улучшенный сценарий выбора расписания

## Цель

Сделать создание регулярного платежа понятным: пользователь выбирает периодичность, день месяца или недели, а даты вводит в формате `ДД.ММ.ГГГГ`.

## Реализовано

- в `RecurringPayment` добавлены `ScheduleDayOfMonth` и `IsLastDayOfMonth`;
- добавлена EF Core миграция `ImprovedPaymentSchedule`;
- месячный платеж сохраняет исходный день и после февраля/короткого месяца возвращается, например, с 28-го на 31-е число;
- поддержано правило «последний день месяца»;
- еженедельный платеж принимает день недели через русскоязычные кнопки;
- ежегодный платеж принимает дату `ДД.ММ.ГГГГ`;
- в сценарии добавления используются кнопки периодичности, дней месяца, дней недели и быстрых дат;
- даты в прошлом отклоняются;
- старый ISO-формат `ГГГГ-ММ-ДД` оставлен для совместимости;
- добавлены unit-тесты короткого месяца, правила последнего дня и перехода из високосного года.

## Проверка

- `dotnet build PersonalAssistant.sln --no-restore`;
- `dotnet test PersonalAssistant.sln --no-restore`;
- 68 unit-тестов и 1 integration test проходят.

## Ограничения

В текущем варианте используются Reply Keyboard-кнопки, так как сценарий создания уже работает через последовательные сообщения. Полноценный inline-календарь можно добавить отдельной UX-задачей, если он потребуется после проверки сценария на VPS.
