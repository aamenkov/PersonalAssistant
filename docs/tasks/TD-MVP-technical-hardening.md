# TD-MVP. Техническое усиление перед первым пользователем

## Решение по техническому долгу

Для ограниченного запуска были важны не все пункты старого списка. Реализованы эксплуатационные риски TD-001 и TD-002. TD-003 и TD-004 удалены из `TODO.md`: декомпозиция `TelegramPollingService` и полный контракт результатов не блокируют запуск, не исправляют конкретный пользовательский дефект и увеличивают риск регрессий.

## Реализовано

- добавлен `/health`, который проверяет подключение к PostgreSQL и возвращает `503` при недоступности базы;
- Docker Compose публикует порт `8080` приложения;
- логи переведены на JSON-формат для удобного просмотра на VPS;
- миграции защищены PostgreSQL advisory lock;
- добавлена таблица `ProcessedTelegramUpdates` и миграция `AddTelegramUpdateIdempotency`;
- повторный Update пропускается после успешной обработки;
- незавершенная заявка освобождается при ошибке Telegram/API или обработчика и может быть повторена после таймаута;
- сохранены существующие owner-scoped запросы, восстановление `ConversationState` и тесты изоляции на уровне репозитория.

## Почему не делали TD-003 и TD-004

Крупный рефакторинг обработчика перед первым пользователем не дает функциональной ценности. Его следует возвращать только при измеримой проблеме: сложность добавления сценария, повторяющиеся ошибки маршрутизации или длинные сообщения, которые реально не помещаются в Telegram.
